## 三、数据模型

### 3.1 SQLite 表结构

| 表名 | 说明 | 主要字段 |
|------|------|----------|
| `t_work_orders` | 工单 | wo_id, room_no, work_type, status, assignee, priority |
| `t_rooms` | 房间 | room_no, floor, building, room_type, status, guest_name |

| `t_room_types` | 房型 | type_id, name |
| `t_floors` | 楼层 | floor_id, building, floor |

| `t_guests_log` | 客人日志 | 入住/退房记录 |

### 3.2 工单状态流转

```
pending → assigned → in_progress → done
   │         │           │
   │         └─→ pending (转单)
   │                     │
   └─→ done (客人直接确认完成)
```

## 四、核心模块说明

### 4.1 微信客服消息处理 (wecom_kf.py)

**消息处理流程：**

```
企微回调 → AES 解密 → SHA1 验签 → sync_msg 拉取 → 逐条处理
                                                    ↓
                                        ┌───────────┼───────────┐
                                        ↓           ↓           ↓
                                    系统事件    文本消息    图片/语音
                                    (欢迎语)        ↓        (拒绝)
                                                ┌───┼───┐
                                                ↓       ↓
                                           命令模式  自然语言
                                           (绑定/     槽位抽取
                                            报修/        ↓
                                            状态)    AI 应答
```

**自然语言槽位抽取：**

```python
_extract_slots("1209要两双拖鞋")
# → {room_no: "1209", work_type: "送物", description: "要两双拖鞋", confidence: 0.7}
```

置信度 ≥ 0.5 且有房间号+需求类型时，直接创建工单。

### 4.2 工单通知 (work_orders.py)

**通知链路：**

```
工单状态变更 → _notify_staff_wo_change()
                    ↓
        ┌───────────┼───────────┐
        ↓           ↓           ↓
    文本消息    模板卡片    部门群通知
    (message/   (template   (appchat)
     send)       card)
```

**超时提醒：**

- 后台循环每 10 分钟扫描
- pending 工单超过 15 分钟未接单 → 补推提醒
- 已提醒过的工单不重复提醒

### 4.3 客人档案 (guest_profile.py)

**数据结构：**

```json
{
  "room:1206:张三": {
    "room_no": "1206",
    "guest_name": "张三",
    "first_seen": "2026-09-11 10:00:00",
    "last_seen": "2026-09-11 11:00:00",
    "preferences": {
      "work_types": {"送物": 3, "送餐": 1}
    },
    "history": [
      {"wo_id": "WO-xxx", "work_type": "送物", "description": "两双拖鞋", ...}
    ]
  }
}
```

**用途：**
- AI 应答时注入客人历史上下文
- 提供个性化服务建议

### 4.4 会话质检 (wecom_kf.py)

**日志格式 (kf_sessions.jsonl)：**

```json
{"ts": "2026-09-11 10:00:00", "external_userid": "xxx", "role": "user", "content": "要两双拖鞋"}
{"ts": "2026-09-11 10:00:01", "external_userid": "xxx", "role": "ai", "content": "好的，已为您安排..."}
{"ts": "2026-09-11 10:05:00", "external_userid": "xxx", "role": "handoff", "content": "ai → human", "extra": {"reason": "客人要求转人工"}}
```

## 六、安全设计

### 6.1 凭证管理

```
敏感凭证 → .wecom_secrets (0600)
         ↓
    启动时加载到 os.environ
         ↓
    wecom_sync.get_agent_secret() 读取
         ↓
    三层优先级: .wecom_secrets > env > 运行时配置
```

### 6.2 权限控制

| 角色 | 权限 |
|------|------|
| super_admin | 全部权限 |
| manager | 管理后台 + 工单分配 |
| employee | 员工工作台 + 自己的工单 |
| guest | 只读（通过 OAuth 自动识别） |

### 6.3 输入校验

- XML 解析拒绝 DTD/实体声明（防 XXE）
- 工单号、房号格式校验
- SQL 参数化查询（SQLite）
- 敏感字段不回显
